Claude(claude.ai)와 함께 기획·1차 제작한 포트폴리오 사이트입니다.
이 폴더를 Claude Code로 열어서 이어서 다듬으면 됩니다.

## 프로젝트 상세 모달

각 프로젝트 카드(아코디언) 안에 **"상세 보기 →"** 버튼이 있고, 클릭하면 Overview / 기획배경 / 한 일 / 툴·배운점 구조의 상세 모달이 열립니다. `assets/images/projects/`의 이미지는 원본 제안서 PDF·PPTX(데스크탑 보관본)에서 페이지를 렌더링해 직접 크롭한 것입니다 (Python이 이 환경에서 동작하지 않아 Node.js + pdfjs-dist + @napi-rs/canvas로 렌더링).

**비주얼: 화이트 카드 레이아웃** — 콘텐츠 구조(Overview/기획배경/한 일/툴·배운점)와 카드 기반 레이아웃 원칙은 그대로 두고, 컬러 팔레트를 화이트/라이트 톤으로 다시 조정했습니다(처음엔 다크 배경으로 리디자인했다가, 가독성과 사이트 톤 통일을 위해 화이트 배경으로 전환). 모달 오버레이 자체는 여전히 어두운 반투명 스크림(`rgba(10,10,10,0.78)` + `backdrop-filter: blur(6px)`)이라 뒤 페이지가 은은히 어두워지고, 그 위로 화이트 모달 패널이 카드처럼 떠 있는 구조입니다.

- **베이스 컬러**: 모달 패널 배경 `#FAFAFA`, 텍스트 `#1E293B`(제목)/`#334155`(본문)/`#64748B`(메타·캡션). 섹션 카드와 스탯 블록의 서피스는 `#F1F5F9` + `#E2E8F0`(슬레이트 계열) 보더로 배경과 구분됩니다.
- **포인트 컬러는 블루·네이비 계열**: 카테고리 라벨, 섹션 라벨(`01 / OVERVIEW` ~ `04 / TOOLKIT`), 스탯 숫자, 리스트 불릿, 닫기 버튼 호버에 `#2563EB`(메인 블루)를 사용합니다. **사이트 메인 페이지(히어로 다크 톤 + 레드 `#E5342A`)와 카드뉴스 라이트박스는 그대로 두고, 프로젝트 상세 모달 내부에만 적용된 색상**입니다 — `.modal-*` 클래스로 스코프가 분리되어 있어 다른 컴포넌트에 영향이 없습니다.
- **스탯 블록**: 프로젝트 안의 핵심 숫자(설문 참여자 수, 가격, 응답률 등)를 `modalStats` 그리드로 상단에 강조합니다 — `projectDetails.{key}.stats` 배열(JS)에 `{ value, label }`로 정의하며, 새 프로젝트를 추가할 때 이 배열도 함께 채우면 됩니다.
- **이미지 프레이밍**: 화이트 배경에서 무거워 보이지 않도록 그림자를 옅게(`box-shadow: 0 8px 22px rgba(0,0,0,0.09)`) 조정하고, 얇은 그레이 보더(`#E5E5E5`)로 이미지 경계를 명확히 했습니다.
- 스크롤(모달 내부 `overflow-y:auto`)과 닫기(Escape/배경 클릭/닫기 버튼) 로직은 변경하지 않았고, 컬러 전환 후 Playwright로 재검증했습니다. 사이트 배경(라이트) → 어두운 스크림 → 화이트 모달로 이어지는 톤 전환도 스크린샷으로 확인했습니다.

### 데이터 차트 (Chart.js)

Brand In:U 모달의 설문조사·가격 데이터는 기존 정적 스크린샷 4장(`brandinu-chart-bar.png`, `brandinu-chart-donut.png`, `brandinu-price-compare.png`, `brandinu-price-grades.png`) 대신 **Chart.js(+ `chartjs-plugin-datalabels`, CDN)로 렌더링하는 실제 차트**로 교체했습니다. 원본 수치는 스크린샷에서 그대로 읽어와 유지했습니다(창작 없음):

- **도넛** — 짐 보관함 필요성: 필요하다 63.45% / 필요없다·의견없음 36.55%
- **바(가로)** — 광장 내 필요 편의시설 응답 5개 항목(짐 보관함 37명 · 보조배터리 대여 18명 · 우비 대여소 9명 · 그늘막 5명 · 흡연부스 5명)
- **그룹 바** — 좌석 등급별(A/B/C) × 구좌 수(1/2/3) 스폰서십 패키지 가격표

색상은 등급/강조 위계에 맞춘 블루 단일 램프(`#1E3A8A` 진한 네이비 → `#2563EB` 메인 블루 → `#93C5FD` 라이트 블루)를 사용했고, 모든 차트에 값 라벨(`chartjs-plugin-datalabels`)과 범례를 직접 표시해 호버 없이도 수치를 읽을 수 있게 했습니다. 차트는 `projectDetails.brandinu.media`의 `{ type:'chart', kind:'bar'|'donut'|'groupedBar', chartId, caption }` 항목으로 정의되고, `renderMedia()`가 `<canvas>`를 생성한 뒤 모달이 열릴 때 `renderBrandinuCharts()`가 각 캔버스에 차트를 그립니다(모달을 열 때마다 캔버스가 새로 생성되므로 별도 `destroy()` 없이 매번 새 Chart 인스턴스를 붙입니다).

**"가격 산정 — 유사 규모 시설 비교" 섹션은 차트가 아니라 참고→산정 근거 카드**입니다. 원래 이 자리에 CGV 강남 vs 인천유나이티드를 나란히 비교하는 막대그래프 2개(관람객 수, 임대료)를 넣었는데, 이 데이터는 "두 대상을 비교"하는 게 아니라 "CGV 강남 사례를 참고해서 우리 가격을 도출했다"는 근거 자료라서 비교 차트가 맥락을 왜곡한다는 피드백을 받아 다시 만들었습니다.

- 좌: **참고 사례(CGV 강남)** 카드(중립 배경, 회색 숫자) → 화살표(→, 모바일에서는 ↓로 회전) → 우: **우리 산정(인천유나이티드)** 카드(연한 블루 배경, 블루 숫자로 강조)
- 각 카드 안 숫자는 스탯 배지와 통일감 있게 큰 숫자 + 작은 라벨 구조
- 하단에 산정 로직 한 줄 설명 — "관람객 규모 대비 비례 산정: 인천유나이티드 관람객(19만 명)은 CGV 강남(57만 명)의 약 1/3 규모이고, 임대료 200~230만원도 CGV 강남 600~700만원의 정확히 같은 1/3 비율입니다(비교가 아니라 실제 산정에 쓰인 근거).
- 데이터/렌더링은 `projectDetails.brandinu.media.work`의 `{ type: 'reference-compare', label, data: { reference, result, note } }` 항목과 `renderCompareBlock()` 함수로 구현했고, `.modal-compare-*` CSS 클래스로 스타일링했습니다. 이 섹션에는 `<canvas>`가 없으므로 Chart.js를 거치지 않습니다.
- 같은 모달의 다른 두 차트(설문조사 결과 도넛+바, 등급별 패키지 가격 그룹 바)는 실제 분포·비교를 보여주는 데이터라 차트 형태를 그대로 유지했습니다.

헬스케어·MD패치 프로젝트는 원본 자료에 차트로 표현할 만한 다항목 수치 데이터가 없어(가격 범위 등 단일 값 위주) 차트로 전환하지 않고 기존 스탯 블록 형태를 유지했습니다.

원본 PNG 4장은 `assets/images/projects/`에 그대로 남아 있습니다(더 이상 `index.html`에서 참조되지 않지만, 원본 근거 자료로 보존).

- `healthcare-sns-*.jpg` — SNS(인스타그램) 게시물 목업 2장
- `mdpatch-product.jpg`, `mdpatch-usage.jpg` — 제품 목업, 착용 예시(Adobe Firefly 생성, 출처 캡션 유지)
- `brandinu-internal-*.jpg`, `brandinu-external-*.jpg` — 내부 광고 포화 / 외부 공간 방치 현황
- `brandinu-gate-*.jpg` — 게이트 유형 3종(터널형·대문형·로비형)
- `brandinu-eg2-*.jpg` — AMOREPACIFIC EG2 GATE 적용 사례
- `brandinu-chart-*.png` — 팬 설문조사 결과(막대·도넛 차트)
- `brandinu-price-*.png` — 가격 산정표 · 등급별 패키지 가격표

## 프로젝트 카드 미리보기 (아코디언, 모달 열기 전 화면)

프로젝트 카드를 클릭하면 펼쳐지는 아코디언(= "상세 보기" 버튼을 누르기 전 미리보기 화면)의 레이아웃을 **헬스케어·MD패치 두 프로젝트에 한해서만** 좌우 2단 구조로 바꿨습니다. Brand In:U는 기존 레이아웃 구조(왼쪽 표지 이미지 1장 + 오른쪽 요약 텍스트/태그/AI노트/버튼)를 그대로 유지합니다 — 레이아웃이 이미 만족스럽다고 확인된 부분은 건드리지 않았습니다(단, AI 노트·버튼 "스타일"은 아래처럼 세 카드 공통으로 강조했습니다).

- **좌측 (~58%, `proj-preview-media`)**: 상세 모달에서 쓰던 실제 상품 사진을 메인 비주얼로 재사용 — 헬스케어는 `healthcare-sns-1/2.jpg`(SNS 게시물 목업 2장), MD패치는 `mdpatch-product.jpg` + `mdpatch-usage.jpg`(제품 목업 + 착용 예시)를 세로로 쌓아 각각 카드 프레임(보더 + 은은한 그림자)에 담았습니다.
- **우측 (~42%, `proj-preview-text`)**: 이미지가 아니라 실제 텍스트로 Overview / 기획배경을 정리했습니다(`projectDetails`에 있는 문구를 그대로 사용). 내용이 넘치면 자체 스크롤(`max-height:420px`, 모바일 300px)이 생기는 박스형 텍스트 블록이며, 섹션 라벨은 모달과 통일감 있게 블루 액센트(`#2563EB`) mono 라벨로 표시했습니다.
- **하단**: 태그, AI 활용 노트, "상세 보기 →" 버튼은 2단 레이아웃 전체 폭을 쓰는 `proj-preview-footer`로 이동했습니다(스타일 자체는 아래 "AI 노트 · 상세 보기 버튼 강조" 참고).
- 구현은 `.proj-body-inner`에 `.proj-preview` 클래스를 추가해 그리드 비율만 `1.3fr 1fr`로 오버라이드하는 방식이라(HTML은 헬스케어·MD패치 카드만 수정), Brand In:U 카드의 레이아웃 구조는 전혀 건드리지 않았습니다. 700px 이하에서는 `.proj-preview`도 1열로 스택됩니다.
- **회귀 주의**: 처음에 모바일 오버라이드를 미디어 쿼리 안에 넣었는데, 그 미디어 쿼리가 순서상 기본 `.proj-preview{grid-template-columns:1.3fr 1fr}` 규칙보다 먼저 나와 있어서(같은 우선순위일 때는 나중에 선언된 규칙이 이김) 모바일에서도 2열이 풀리지 않는 버그가 있었습니다. 기본 규칙을 미디어 쿼리보다 앞에 두는 순서로 고쳤습니다 — 이 파일에 반응형 오버라이드를 추가할 때는 항상 "기본 규칙 → 미디어 쿼리" 순서를 지켜야 합니다.

### AI 노트 · 상세 보기 버튼 강조

세 프로젝트 카드(Brand In:U 포함 전부) 공통으로, 미리보기 하단의 "AI 활용" 노트와 "상세 보기" 링크가 너무 조용해서 눈에 안 띈다는 피드백을 받아 존재감을 높였습니다.

- **AI 활용 노트**: 텍스트 박스 → ✨ 아이콘 + 옅은 블루 틴트 배경(`#EFF6FF`) + 블루 보더(`#BFDBFE`)를 가진 카드로. "AI 활용 —" 라벨도 블루(`#1D4ED8`)로 강조.
- **상세 보기**: 텍스트 링크(밑줄) → 실제 버튼(솔리드 블루 `#2563EB` 배경, 흰 텍스트, 넉넉한 패딩)으로 전환. 화살표를 `<span class="arrow">`로 분리해서 호버 시 `translateX(4px)`로 오른쪽으로 살짝 이동하는 마이크로 인터랙션을 추가했고, 버튼 자체도 호버 시 더 진한 블루(`#1D4ED8`)로 어두워집니다.
- **카드 전체 클릭**: `.proj-body-inner`(미리보기 영역 전체)에 클릭 리스너를 달아서 버튼뿐 아니라 이미지·텍스트·태그 등 어디를 클릭해도 상세 모달이 열리도록 했습니다(`cursor:pointer`로 힌트). 단, 우측 스크롤 텍스트 블록(`proj-preview-text`)은 읽기/스크롤 용도라 `cursor:auto`로 되돌려 놨습니다. 버튼 자체의 클릭 핸들러는 `stopPropagation()`으로 카드 핸들러와 중복 실행되지 않게 분리되어 있습니다.

## 카드뉴스 라이트박스 뷰어

Content Archive 섹션의 카드(썸네일)를 클릭하면 슬라이드를 순서대로 넘겨보는 전체화면 라이트박스가 열립니다. 프로젝트 상세 모달과는 완전히 별개의 UI지만, **컬러 톤은 프로젝트 모달과 동일한 화이트 계열로 통일**되어 있습니다(레드 액센트 `#E5342A`는 그대로 유지).

**비주얼: 코버플로우(coverflow) 스타일, 화이트 배경** — 중앙 슬라이드는 크고 선명하게(scale 1, opacity 1, 옅은 그림자 + 은은한 레드 글로우), 좌우 슬라이드는 카드 개수만큼 3D로 겹쳐 부채꼴로 펼쳐집니다(`translateX` + `translateZ` + `rotateY` + `scale` 조합, offset 1단계는 scale 0.8/opacity 0.62/blur 3px, 2단계는 scale 0.66/opacity 0.4/blur 4px, 그 바깥은 opacity 0으로 사라짐 — 다크 배경 때보다 opacity를 살짝 높여 화이트 배경에서 카드가 날아가 보이지 않도록 조정). 전환은 `cubic-bezier(.22,.68,.36,1)` 이징으로 0.38초. 순환(wrap-around) 시에도 최단 경로로만 회전하도록 offset을 매 렌더마다 다시 계산합니다(`cnOffsetFor`).

배경은 완전 불투명이 아니라 `rgba(250,250,250,0.9)` + `backdrop-filter: blur(8px)`(프로젝트 모달과 같은 화이트/오프화이트 반투명 공식)라 뒤쪽 페이지 콘텐츠가 흐릿한 실루엣으로 비칩니다. 카드 자체도 배경 `#fff` + 얇은 그레이 보더(`rgba(0,0,0,0.08)`) + 옅은 그림자(`rgba(0,0,0,0.14~0.18)`)로 화이트 배경 위에서도 경계가 분명합니다. 화살표(원형 버튼)·점 도트·페이지 번호 텍스트도 다크 그레이 계열(`#1a1a1a`/`rgba(0,0,0,0.22)`)로 바꿔 화이트 배경에서의 대비를 확보했고, 호버 시 레드 액센트는 그대로입니다.

구현 방식: 슬라이드 전체를 `<div class="cardnews-card">`로 한 번에 렌더링해두고(모든 이미지 로드, WebP라 용량 부담 적음), 현재 인덱스와의 offset에 따라 `cnApplyCardStyle()`이 매번 transform/opacity/filter만 갱신합니다. 화살표/도트/키보드/드래그 스와이프/Escape/배경 클릭 등 기존 인터랙션 로직은 변경 없이 그대로 재사용됩니다.

```
assets/images/cardnews/
  kleague-fb/     01.webp ~ 08.webp   (8p)  K리그 F&B 트렌드
  hydration/      01.webp ~ 10.webp   (10p) 하이드레이션 브레이크
  socios/         01.webp ~ 12.webp   (12p) Socios.com 팬 토큰
  manu/           01.webp ~ 10.webp   (10p) 맨유 상장 잔혹사
  uniform/        01.webp ~ 06.webp   (6p)  유니폼 스폰서십의 진화
  nonmatchday/    01.webp ~ 14.webp   (14p) 비경기일 수익화 (원본 PDF에서 페이지 렌더링 추출)

assets/images/cardnews_original_backup/   위와 동일한 구조의 PNG 원본 (사이트에서는 미참조)
```

- 각 폴더는 데스크탑에 보관된 카드뉴스 zip(이미지 시퀀스) 또는 원본 PDF에서 추출한 것입니다. `archive-socios.jpg`(썸네일)의 "10p" 표기와 실제 슬라이드 수(12p)가 어긋나 있던 것을 이번에 바로잡았습니다(맨유 상장 잔혹사도 8p→10p로 수정).
- **포맷**: 원래 PNG로 추출했으나 용량이 45MB(60장)에 달해 `@napi-rs/canvas`로 WebP(quality 88)로 재인코딩 — 총 45MB → 5MB. PNG 원본은 `assets/images/cardnews_original_backup/{slug}/`에 그대로 보관 중이며, 사이트(`index.html`)는 `.webp`만 참조합니다. 원본이 더 이상 필요 없으면 배포 전에 `cardnews_original_backup/`를 지워도 됩니다.
- `index.html`의 `cardNewsManifest` 객체(JS)가 각 시리즈의 제목·슬라이드 수를 정의하고, `cnImagePath()` 함수가 `assets/images/cardnews/{slug}/{NN}.webp` 경로를 생성합니다 — 새 카드뉴스를 추가하려면 `assets/images/cardnews/{slug}/01.webp…`를 채운 뒤 매니페스트에 항목을 추가하고, `.archive-item`에 `data-cardnews="{slug}"`를 달아주면 됩니다. 정적 사이트라 실제 파일 목록을 브라우저가 읽을 수는 없어서, 슬라이드 개수는 이 매니페스트로 명시적으로 관리합니다.
- 인터랙션: 좌우 화살표 클릭, 키보드 ←/→, 터치/마우스 드래그 스와이프(Pointer Events로 통합 처리), 하단 점 도트 클릭 이동, Escape/배경 클릭 닫기. 첫/마지막 슬라이드에서는 순환(wrap-around)합니다.
- 이미지는 카드 안에서 `object-fit:contain`으로 표시되어 잘리지 않습니다. 시리즈를 열 때 전체 슬라이드를 한 번에 로드해두므로(개별 프리로드 불필요) 넘길 때 끊김이 없습니다.

## 레이아웃 QA 패스

프로젝트 모달 3개 + 메인 페이지 전체를 대상으로 정렬·오버플로우·간격 오류만 잡는 QA를 진행했습니다(디자인 자체는 변경하지 않음). `scrollWidth > clientWidth` 비교로 오버플로우를 객관적으로 스캔한 뒤, 실제로 걸린 항목만 스크린샷으로 재확인하는 방식으로 진행했고, 아래는 발견 및 수정한 것들입니다.

- **Chart.js 캔버스가 그리드 트랙을 밀어내는 문제**: `<canvas>`는 기본 intrinsic width(300px)를 가지고 있어서, 2열 그리드 안에 넣으면 그리드 아이템이 트랙 폭 아래로 줄어들지 못해(`min-width:auto` 기본값) 카드/모달이 옆으로 밀리는 오버플로우가 발생했습니다(모바일 390px 기준 최대 441px 초과). `.modal-media-figure`, `.modal-chart-canvas-wrap`에 `min-width:0`을 추가해 해결했습니다.
- **모바일에서 차트 2개가 나란히 있으면 라벨이 잘리는 문제**: 위 오버플로우를 고치고 나니, 좁아진 차트 칸 안에서 이번엔 반대로 라벨 텍스트(항목명, 범례, 도넛 중앙 수치)가 잘리는 문제가 드러났습니다. `@media(max-width:640px){ .modal-chart-figure{ grid-column:1/-1; } }`로 차트가 포함된 그리드 아이템만 모바일에서 전체 폭으로 쌓이도록 처리했습니다(사진 그리드는 영향 없음 — 사진은 텍스트가 없어 좁아져도 문제없이 스케일).
- **도넛 차트 중앙 라벨과 링이 겹치는 문제**: "63.45%"의 `%`가 스크린샷에서 안 보이길래 클리핑 버그인 줄 알았는데, DOM 측정으로는 잘림이 전혀 없었습니다 — 알고 보니 링(블루)과 텍스트(블루)가 같은 색이라 특정 지점에서 겹쳐 보이지 않게 블렌딩된 것이었습니다(디버그 배경으로 확인). `cutout`을 72%→80%로 넓혀 중앙 여백을 충분히 확보해 해결했습니다.
- **프로젝트 카드 아코디언 화살표 회전 시 미세 오버플로우**: 카드가 열려 "+"가 45도 회전해 "×"로 바뀔 때, 회전된 정사각형의 대각선 바운딩 박스가 그리드 트랙 경계를 약간(~6px) 넘는 것을 발견했습니다. `.proj-arrow`에 명시적 width/height를 줘서 22px→22px 정사각형 기준으로 회전하도록 정리해 11px→6px로 줄였습니다(화면에는 보이지 않는 수준의 잔여치 — `body.scrollWidth`는 항상 음수로 실제 가로 스크롤은 발생하지 않음; 완전히 0으로 만들려면 "+"→"×" 회전 인터랙션 자체를 바꿔야 해서 디자인 변경 없이는 이 이상 줄이지 않았습니다).
- **위 화살표 수정 중 발생한 회귀**: `.proj-arrow`에 `display:inline-flex`를 추가하면서 실수로 코드 순서가 모바일 미디어쿼리(`.proj-arrow{display:none}`)보다 뒤로 가버려, 모바일(≤700px)에서 카드가 열렸을 때 원래 숨겨져야 할 화살표(×)가 다시 보이는 회귀가 생겼습니다. 미디어쿼리를 다시 마지막으로 옮겨서 고쳤습니다 — CSS 캐스케이드 순서 실수라, 만약 이 파일에 추가 CSS를 append할 때는 미디어쿼리 오버라이드가 항상 관련 베이스 규칙보다 뒤에 오는지 확인하는 게 좋습니다.
- **스탯 배지 vs 참고→산정 카드 통일감**: `.modal-stat-value`(21px/600)와 `.modal-compare-metric-value`(19px/700)가 서로 다른 크기·굵기였던 것을 통일했고, 카드 padding도 `20px 18px` → `20px 16px`로 맞췄습니다.
- **CSS 변수로 spacing scale 도입**: `--m-space-xs`(6px) ~ `--m-space-2xl`(32px)를 `:root`에 정의하고, 기존에 쓰이던 값과 정확히 같은 값으로 매핑해 `.modal-stat`, `.modal-section`, `.modal-compare-card`, `.modal-chart-canvas-wrap` 등에 적용했습니다. 값 자체는 바뀌지 않은 순수 리팩터링(비주얼 회귀 없음)이며, 앞으로 새 카드형 컴포넌트를 추가할 때 재사용하면 됩니다.

메인 페이지(히어로/About/Projects/Content/Skills/Contact)는 데스크톱(1280px)·모바일(390px) 양쪽에서 스캔한 결과 위 화살표 건 외에는 오버플로우·정렬 문제가 없었습니다.

## 히어로 섹션 리디자인

히어로를 순수 타이포 버전(F, 사진 없이 고스트 타이포 + blob)에서 **사진 배경 버전으로 다시 전환**했습니다. 이전 시도(스톡 사진 → dot 패턴 → 순수 타이포 → 사진 재도입)를 반복한 끝에 최종적으로 서울월드컵경기장 사진 배경으로 확정.

- **배경 사진 교체**: `assets/images/hero-stadium.jpg`(서울월드컵경기장)를 `.hero::before`(이미지, `filter:saturate(0.7) contrast(1.05)`로 톤 다운)와 `.hero::after`(다크 그라디언트 오버레이, `rgba(10,15,30,0.55)→0.85)`) 두 개의 pseudo-element로 분리해서 구현했습니다 — 그라디언트만 텍스트 가독성을 위해 얹고, 이미지 자체엔 필터가 별도로 걸리도록 레이어를 나눴습니다. 히어로 배경이 다시 어두워져서 `--hero-text`/`--hero-muted`/`--hero-border`를 흰색 계열로 되돌리고, 태그 필 배지도 다크 배경 기준(흰 보더/텍스트, 반투명 흰 배경)으로 재조정했습니다.
- **고스트 타이포 제거**: 사진 배경과 겹쳐 지저분해 보이는 대형 고스트 텍스트("SPORTS BUSINESS")와 관련 스크롤 패럴랙스 JS를 삭제했습니다. 이름 stagger fade-in, hover 마그네틱 효과, 라벨 밑줄 draw-in 애니메이션은 그대로 유지하고 색상만 밝은 톤으로 바꿨습니다.
- **CTA 정리**: "이력 보기" 버튼을 삭제하고 "프로젝트 보기" 버튼만 남겼습니다(패딩을 살짝 키워 단독으로 있을 때의 무게감 보정).
- **내비게이션 스크롤 전환**: 내비 바가 히어로 위에서는 투명 배경 + 흰 텍스트, 히어로를 벗어나면(`hero.getBoundingClientRect().bottom <= navHeight`) `nav-scrolled` 클래스가 붙어 불투명 화이트 배경 + 어두운 텍스트로 전환되도록 새로 구현했습니다. 이 로직은 git 히스토리에 존재한 적이 없어서(요청 문구는 "다시 추가"였지만) 이번에 새로 작성한 것입니다.
- **숭의아레나 폴라로이드 카드**: 요청에 "유지"로 언급되었으나 실제로는 `index.html`/git 히스토리/`assets/images/`에 해당 요소(및 `hero-sungui.jpg`)가 존재한 적이 없어 이번 작업 범위에서 제외했습니다. 필요하면 새로 만들어야 합니다.
- 내비 왼쪽 "문준환" 로고 텍스트는 계속 삭제 상태를 유지했습니다.
